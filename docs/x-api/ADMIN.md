# X-API 管理员指南

## 先理解三个对象

| 对象 | 含义 |
| --- | --- |
| 上游账号 | 火山方舟等供应商的 API Key 和请求地址，只由管理员维护 |
| 模型分组 | 用户可选的一组模型及计费规则，密钥绑定到分组 |
| 用户密钥 | X-API 自己签发的凭证，使用者拿它调用 X-API |

用户拿到的是 X-API 密钥，不是你的火山密钥。

## 本地首次登录

1. 启动后打开 `http://127.0.0.1:18080`，点击登录。
2. 邮箱 `admin@x-api.local`，密码见 `.local/environment.json` 的 `ADMIN_PASSWORD`。
3. 阅读并确认上游保留的管理员说明。
4. 在个人资料中修改密码。修改后，启动配置中的初始密码不会自动同步；它也不会覆盖数据库中的新密码。

本地默认允许邮箱密码注册，新用户默认额度为 0。邮件验证码默认关闭，因此没有 SMTP 也能完成本地注册。后续上线前再配置 SMTP、验证码注册和找回密码；当前可在已登录状态修改密码，管理员也可管理用户密码。

## 豆包上游接入

### 火山方舟侧

在火山方舟确认目标模型的免费额度，开启符合条件的「安心体验」模式，并完成模型服务开通。创建 API Key，复制该账号实际可调用的模型 ID。

模型名以供应商控制台为准，例如 `Doubao-Seed-2.1-lite` 是展示名，调用时可能需要带版本的模型 ID。不要直接拿展示名替代调用 ID，也不要把它改名成 GPT 模型。

### X-API 侧

1. **分组管理**：新建普通/标准分组，例如「豆包测试」。平台选 OpenAI 兼容接入所用的 `OpenAI`，倍率初始设 1，允许目标用户使用该分组。
2. **账号管理**：添加 OpenAI 平台的 API Key 类型账号，填写火山密钥。
3. Base URL 填写 `https://ark.cn-beijing.volces.com/api/v3`。选择 Chat Completions 转发；账号高级设置中的 Responses 模式可设为强制 Chat Completions，避免依赖自动探测。
4. 在账号支持模型/模型映射中明确加入真实模型 ID，采用**同名映射**：

   ```json
   {
     "你在方舟看到的实际模型ID": "你在方舟看到的实际模型ID"
   }
   ```

5. 将账号关联到刚建的分组，并保持账号启用、可调度。
6. 在分组的模型定价配置中，为真实模型配置输入、输出价格。界面的金额单位以字段标签为准；内部接口的 `input_price` / `output_price` 是 USD/token，不能直接填每百万 token 的价格。比如每百万 token 1 USD 对应内部值 `0.000001`。
7. 打开用户端「可用模型」，确认分组和真实 ID 已出现。只配置账号、没有明确模型列表时，X-API 会显示空列表。

当前标准目录忽略通配符和改名映射，且不会补齐上游预设模型。第一版重点支持同名配置的文本模型；订阅账号、合成分组和其他协议应在后续单独验收。

## 手动分配额度

1. 用户通过注册页面创建自己的账号。
2. 管理员在「用户管理」找到该用户，使用「分配额度」。
3. 填写额度并记录备注，例如「本地联调额度」。
4. 用户登录后查看额度，在「API 密钥」新建密钥，选择对应分组。
5. 用户从「可用模型」复制 ID，按「接入指南」发送请求。

额度分配是站内记账操作，不代表向上游充值。建议从小额度开始；上游免费额度耗尽时，即使站内还有余额，供应商请求也可能失败。

## 检查调用

- 非流式：`stream: false`，确认返回模型回答。
- 流式：`stream: true`，确认逐步返回且正常结束。
- 查看用户用量和后台记录：模型 ID、输入/输出 token、扣费与状态。
- 停用密钥后，再次调用应被拒绝。
- 请求未配置的模型应失败。

真实豆包验收仍需供应商服务已开通、密钥有效且有额度。项目的模拟集成测试只证明本地转发与管理逻辑。

## 运行与数据

独立端口为 18080 / 25432 / 26379；与旁边 Sub2API 的 8080 / 15432 / 16379 分开。

本地日志与配置均在 `.local/`。停止请使用 `python3 scripts/local.py stop`。数据卷不会因停止而删除，生产备份方案将在云端部署阶段完成。
